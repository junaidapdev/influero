## Decisions Made During Build

_Add decisions here as they are made during implementation._

- Backend + frontend = separate folders in one monorepo (deliberate override of code-review point 5; rationale in `02-architecture.md`).
- Backend platform: Supabase (Postgres + auth + storage + edge functions on Deno + realtime).
- Edge runtime is Deno → no server-side PDF rasterization. PDFs converted to PNG client-side (pdf.js); edge function only ever receives an image.
- Snap result delivery via Supabase realtime, not polling.
- Dates: store ISO/Gregorian (UTC); display Hijri (Umm al-Qura) + Gregorian, Hijri leading in Arabic locale.
- Reminders created in application/edge code, not Postgres triggers (visible, testable, debuggable).
- Profile table named `app_users` (auth `users` is Supabase's; `app_users` is our extension).
- DB transactions on Supabase = Postgres functions (RPC) with `security invoker`, called from edge functions; canonical case is `mark_payment_received`.
- Edge-function ownership default: `createSupabaseAsUser` (forwards caller's JWT, RLS still applies). `createSupabaseAdmin` (service role) reserved for explicit, ownership-checked cases.
- Deploy: frontend on Vercel; backend on Supabase. Accounts already provisioned (Supabase project, OpenAI, Google OAuth).

**Feature 02 — Auth (architect-planned; bundled with i18n shell + app_users prereqs):**
- **Resequence (developer-approved):** i18n shell → `app_users` table+RLS → full Auth. Auth's login UI needs i18n, and its profile bootstrap needs the table — building strictly in number order would have shipped hardcoded strings + a non-functional bootstrap.
- **Profile bootstrap = client-side idempotent upsert** (`hooks/useEnsureAppUser.ts`), `upsert(..., { onConflict: 'user_id', ignoreDuplicates: true })` under the user's own session (RLS `insert own`). No Postgres trigger — matches the project's "application code, not triggers" stance; self-heals because idempotent; preserves later user edits. Seeds `display_name`/`avatar_url` from OAuth metadata when present.
- **OAuth = PKCE flow** (`flowType: 'pkce'` + `detectSessionInUrl: true`). `/auth-callback` waits for the session (client auto-exchanges the code on load) rather than calling `exchangeCodeForSession` manually. Has a 10s timeout fallback to `/login`. **Caveat:** PKCE email-confirmation is same-device (code verifier lives in that browser's storage) — documented in `library-docs.md`.
- **Email/password:** `signUp` with `emailRedirectTo` → when `data.session === null`, show the "check your email" VerifyNotice. Email link returns through `/auth-callback`.
- **i18n core only now:** date/currency/number formatters (rest of Feature 03) deferred to their first real consumer so they're not built untested.
- **`@shared/` alias added** (vite + tsconfig) → `backend/shared/` is in the frontend's tsconfig `include`; `AppUser` type lives there, framework-agnostic, exercised via `Pick<>` in `useEnsureAppUser`. This is the seam the future RN app reuses.
- **UI primitives are hand-rolled, token-exact** (`components/ui/{Button,Input,Label,FieldError,LocaleToggle}`) — NOT shadcn/ui. `shadcn init` against Tailwind v4 would rewrite `index.css` and risk clobbering the `@theme` tokens. Architecture.md says `components/ui` = shadcn primitives; this is a deliberate deviation. **Decision (developer-confirmed): stay hand-rolled.** Swapping to real shadcn later remains a clean, optional change.
- **tsconfig:** removed deprecated `baseUrl` (TS 7.0); `paths` resolve relative to tsconfig under `moduleResolution: bundler`. Added `resolveJsonModule` for the locale JSON imports.
